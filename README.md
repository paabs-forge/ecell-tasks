# E-Cell UIET KUK — Selection Tasks

This repository contains my work across the E-Cell UIET KUK selection tasks.

I approached the three tasks as parts of one connected experience rather than as three unrelated webpages. Each page has a different purpose, so I intentionally gave each one its own visual language instead of forcing the same design everywhere.

## How I Intended the Projects to Be Viewed

The projects are connected through their navigation.

The intended journey is:

Task 3 — Startup Showcase
→ Task 2 — E-Cell Website
→ Task 1 — Startup Registration

Task 2 provides the main E-Cell context and links to the Task 1 registration experience.

Task 3 represents a separate startup showcase experience and its **Official Site** link takes the visitor back to Task 2.

This was intentional. I wanted the projects to feel like parts of the same ecosystem while still having clearly different purposes.

## Task 1 — Startup Pitch Competition

Task 1 focuses on the actual registration experience for a Startup Pitch Competition.

The intention here was to make the page feel like a real competition registration portal rather than a generic form. The darker visual treatment with amber accents was chosen to give it a focused, event-oriented character and to make the registration action feel important.

The form is connected to a Google Apps Script backend and Google Sheet, so this task goes beyond simply designing the interface. It demonstrates the complete flow from entering information to processing and storing a registration.

Live Demo:

https://paabs-forge.github.io/ecell-tasks/task-1/

## Task 2 — E-Cell Website

Task 2 is intended to establish the broader identity and presence of E-Cell UIET KUK.

Rather than treating it only as a page for one event, I approached it as the central point from which someone could understand the organisation and move toward its activities.

It also acts as the connection between the other tasks. The registration CTA leads toward Task 1, while Task 3 uses Task 2 as its Official Site.

Live Demo:

https://paabs-forge.github.io/ecell-tasks/task-2/

## Task 3 — Startup Showcase

Task 3 was designed around a different idea: instead of asking someone to register immediately, the page first lets them discover startups and understand what other builders are working on.

The visual direction is deliberately cleaner and lighter than Task 1. The blue-and-white treatment was chosen to make the showcase feel open, modern, and discovery-oriented.

The page follows an event journey:

Discover the showcase
→ Meet the builders
→ Search and filter startups
→ Explore a startup
→ Visit its site
→ Pitch your own startup

The continuously moving **Explore** and **Connect** elements in the hero were added to reinforce that idea of movement between discovering people and connecting with them.

## Design Intent

One of my main intentions across these tasks was to avoid building interfaces that only satisfy the visible checklist.

I tried to make each page communicate its purpose through its visual hierarchy and interaction:

- Task 1 feels focused on participation and registration.
- Task 2 establishes the organisation's broader identity.
- Task 3 focuses on discovery, builders, and startup exploration.

I also deliberately avoided adding functionality simply because it was possible. I preferred keeping the interfaces focused on what the particular page is supposed to accomplish rather than adding unnecessary sections or interactions.

The goal was not to make every page look identical. The goal was to make the three pages feel related while allowing each one to communicate its own purpose clearly.

## What I Wanted the Work to Show

Beyond completing the individual tasks, I wanted the repository to demonstrate how I think about building a website:

- Start with the purpose of the page.
- Decide what the visitor should do next.
- Build the visual hierarchy around that journey.
- Add interaction where it improves the experience.
- Keep functionality honest instead of pretending a demo does more than it actually does.
- Connect separate pieces when there is a meaningful reason to connect them.
- Avoid adding complexity just to make a project appear larger.

These projects are therefore less about how many elements I could put on a page and more about how I chose what belonged there.

Every task also has a detailed README inside its respective folder if you want to explore the implementation in more detail.
